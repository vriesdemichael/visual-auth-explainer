Settings

Adds proof of who logged in on top of the access OAuth grants.

Client type

Whether the app can keep a secret. One that cannot, such as an app in a browser, has to rely on PKCE.

The app proves it started this login, so a stolen code is no use alone. Current advice is to have it on, and a public client must.

Token type

Whether holding the token is enough, or the app must also prove it holds a key.

The IdP hands the login to another IdP. The app does not notice.

App to IdP

POST /token

The app trades the code for tokens

The app trades the code for tokens on a direct call. A public client has no secret to prove who it is, but it does have the verifier, which was never sent through the browser. Someone who only saw the code cannot do this. If the app runs in the browser, this call comes from its own JavaScript.

Direct. One system calls another, with no redirect through the browser. Also called the back channel.

Recorded from Keycloak 26.8.1 on 2026-11-01.

What if someone else gets hold of the code?

They get nothing. They would also need the verifier, and it has never left the app. The challenge they may have seen cannot be turned back into it.

In Keycloak: Client authentication

Off, which makes this a public client. Turn it on and this request gets a 401 without a secret.

Clients › your client › Settings › Capability config › Client authentication

Tried on 26.8.1: changing it changes this.

In Keycloak: Require PKCE

Someone with only the code gets a 400 invalid_grant: PKCE code verifier not specified. That try also uses up the code, so the real app has to start the login again.

Clients › your client › Settings › Capability config › Require PKCE

What it carries

  • grant_type=authorization_code body Says what the app is trading in for tokens.
  • code body The one-time code, which the app trades for tokens.
  • redirect_uri body Has to be the address the code was sent to.
  • client_id body Says which app this is, as registered in setup.
  • code_verifier body Sent now, and never through the browser From: PKCE
