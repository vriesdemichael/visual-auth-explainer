Settings

Adds proof of who logged in on top of the access OAuth grants.

Client type

Whether the app can keep a secret. One that cannot, such as an app in a browser, has to rely on PKCE.

The app proves it started this login, so a stolen code is no use alone. Current advice is to have it on, and a public client must.

Token type

Whether holding the token is enough, or the app must also prove it holds a key.

The IdP hands the login to another IdP. The app does not notice.

Stored upstream tokens

The IdP keeps the upstream IdP's tokens, and the app can ask for them.

Here because of: Stored upstream tokens

In Keycloak: Allow retrieve external tokens

Lets this client ask for stored tokens, from the providers named in Allowed Identity Providers for External Tokens. The console only shows it on a server with API V2 on.

Clients › your client › Settings › Capability config › Allow retrieve external tokens

Flag identity-brokering-api:v2: supported, off by default

Tried on 26.8.1: changing it changes this.

In Keycloak: A server option

API V2 needs the server started with this flag, and that turns API V1 off, which the docs do not say. Set it where the server starts. It is not in the admin console.

--features=identity-brokering-api:v2

Tried on 26.8.1: changing it changes this.
