Settings

Adds proof of who logged in on top of the access OAuth grants.

The identity provider asks the user whether the app may have this access.

Client type

Whether the app can keep a secret. One that cannot, such as an app in a browser, has to rely on PKCE.

The app proves it started this login, so a stolen code is no use alone. Current advice is to have it on, and a public client must.

Token type

Whether holding the token is enough, or the app must also prove it holds a key.

The server rejects the first proof, to limit how long a proof can be used.

The IdP hands the login to another IdP. The app does not notice.

Stored upstream tokens

The IdP keeps the upstream IdP's tokens, and the app can ask for them.

Which setting controls each message, on the server this was recorded from. Off, it is the protocol and nothing else.
