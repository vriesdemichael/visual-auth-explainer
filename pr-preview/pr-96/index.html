Authlines

Flip one thing. Watch the login change.

OAuth and OpenID Connect on one living diagram, with its messages recorded from a real Keycloak, a free identity provider you can run yourself. The specs are the same elsewhere, though error codes, token formats, defaults and the stored-token API are Keycloak's own. Pick a question and follow it, one message at a time. New to this? Start with the first one.

  1. Start here

    What everything else builds on, in plain words.

    1. How does an app get access? An app acts for a user, without ever seeing their password.
    2. Why not just send the token back through the browser? Why the browser only gets a code, and what happened to the way that did not.
    3. What can the browser see? The whole flow with everything the browser was not sent hidden.
    4. How does an app know who logged in? Access is not identity, which is what OpenID Connect adds.
    5. When does the user get asked? What a scope is, and why you may never have seen the question.
    6. What is single sign-on? Why don't I log in twice? A second app, the same login, and no password.
    7. How do an app and a provider get to know each other? What people have to do before anyone can log in.
    1. I have to add login to an app. What do I do? The part you do once, which part of your code is left, and what a library does.

  2. Keeping it safe

    What can go wrong, and what stops it.

    1. What is different about an app with no secret? An app in a browser or on a phone cannot keep one, so what proves who it is?
    2. What if someone steals the code? Watch them take it as it crosses the browser, and get the tokens.
    3. How does PKCE work? The app proves it started this login, with a value that was never in a redirect.
    4. What does PKCE do to the attacker? The same attempt, a different answer, and a cost that remains.
    1. Can a code be stolen from an app with a secret? They get the code, but cannot trade it. That is not the end of it.
    2. Does an app with a secret need PKCE too? Why current advice says yes, even when a stolen code is not enough alone.
    3. What does an attacker get against both? A secret and PKCE together, against the same attempt.
    1. What is a stolen refresh token worth? More than the access token, and a new one coming back may not stop it.
    2. How does DPoP stop a stolen token being used? It ties a token to a key that never leaves the app. The theft itself is not drawn.
    3. How can a proof be stopped from being used later? A nonce from the server. The spec allows it, and Keycloak did not ask.

  3. Logging in somewhere else

    When the identity provider hands the login to another one.

    1. How do you log in with another provider? The app does not notice, and that is the point.
    2. How does the app call the other provider's API? Advanced The identity provider kept its tokens, and hands them over.
    3. What changes with API V2 for stored tokens? Advanced Only the access token, and the client has to be allowed to ask.

  4. Setting up a real app

    The combinations people use, with what is really sent.

    1. What does my API have to check? A token says nothing until someone has looked.
    2. What happens when the token runs out? The app gets a new one, and the user never knows.
    1. What does log out actually do? Two sessions end, if you ask for both, and an access token keeps working.
    2. I logged out. Does the token still work? The same token, and two answers.
    3. Am I logged out of my other apps too? They lose the session they relied on, and may not know yet.
    1. A web app on a server Advanced It can keep a secret. With OpenID Connect to know who logged in, and PKCE on top.
    2. An app that runs in the browser Advanced No secret to keep, so PKCE protects the code. The tokens then live in the page, which is the harder problem.

  5. Under the hood

    For when you are looking at the real thing and something is off.

    1. Why did my API say 401? Advanced It does not accept the token, for one of several reasons that look the same.
    2. What is the difference between 401 and 403? Advanced One is about the token, and the other about what it allows.
    3. What does an API say to a call with no token? Advanced Which kind of token it wants, and no error.
    4. What if someone changes what a token says? Advanced Anyone can read one, and nobody else can sign it.
    5. Why does my API refuse a token that is still good? Advanced It has to be for this API, and it is not until someone arranges that.
    1. What really goes over the wire? Advanced The raw request and answer, from one real run.
    2. Why do I get Invalid parameter: redirect_uri? Advanced Where the address is checked, and where it was registered.
    3. Do two apps share a token? Advanced They share a login, and each has tokens of its own.
    4. How do I make someone log in again? Advanced A session is usually good enough. One parameter says not this time.
    5. Why do I get login_required? Advanced Someone would have to log in, and the server was told not to ask.
    6. Why do I get Maximum allowed refresh token reuse exceeded? Advanced A refresh token was used twice, and that ended things for this app.
