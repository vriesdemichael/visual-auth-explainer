Refused: this one has been used

Refused, because here each works once. A second use means a copy exists, or the app sent it twice, and the server cannot tell which, so this also ends things for the newest one.

In practice. Whether it works is up to the server. RFC 9700 says a 's refresh tokens have to work only once or be tied to the sender, so check what yours does.

Direct.

Here because of: When the token runs out

In Keycloak: Revoke Refresh Token

Off by default, so the old refresh token keeps working though a new one came back, on a client with no secret too. RFC 9700 asks more than that of a public client, so this is the setting to look at. Turn it on and a second use says Maximum allowed refresh token reuse exceeded, and then the newest one says Session doesn't have required client, because the second use ended the session for that client.

Realm settings › Tokens › Revoke Refresh Token
