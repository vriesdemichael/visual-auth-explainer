Run it yourself

This is the server the recordings came from, Keycloak 26.8.1, with the same names. You need Docker, a browser and a terminal, and a few minutes once Docker has fetched the image. A real login, a real code in your own address bar, and real tokens.

Everything here is a throwaway value for a server on your own machine. Never paste real secrets into these commands, and do not run this anywhere other people can reach it.

These fit the settings you came from: an app with a secret. Other settings are not part of this walk.

1. Start the server

In an empty folder. It stays running in that terminal, and it is ready when it says Listening on: http://0.0.0.0:8080. Inside the container, that is. It only takes connections from your own machine.

cat > demo-realm.json <<'EOF'
{
  "realm": "demo",
  "enabled": true,
  "accessCodeLifespan": 300,
  "users": [
    {
      "username": "alice",
      "email": "alice@example.test",
      "firstName": "Alice",
      "lastName": "Example",
      "enabled": true,
      "emailVerified": true,
      "credentials": [
        {
          "type": "password",
          "value": "throwaway-password",
          "temporary": false
        }
      ],
      "realmRoles": [
        "default-roles-demo"
      ]
    }
  ],
  "clients": [
    {
      "clientId": "demo-app",
      "enabled": true,
      "standardFlowEnabled": true,
      "redirectUris": [
        "http://localhost:9100/callback"
      ],
      "publicClient": false,
      "clientAuthenticatorType": "client-secret",
      "secret": "throwaway-client-secret"
    }
  ]
}
EOF
docker run --rm --name authlines-demo -p 127.0.0.1:18080:8080 \
  -e KC_BOOTSTRAP_ADMIN_USERNAME=admin \
  -e KC_BOOTSTRAP_ADMIN_PASSWORD=throwaway-admin \
  -v "$PWD/demo-realm.json:/opt/keycloak/data/import/demo-realm.json" \
  quay.io/keycloak/keycloak:26.8.1 \
  start-dev --import-realm

On Windows, use WSL or Git Bash. In Git Bash, put MSYS_NO_PATHCONV=1 in front of docker run, or it rewrites the path to the file.

2. Log in, in your browser

Open this address, and log in as alice with the password throwaway-password.

http://localhost:18080/realms/demo/protocol/openid-connect/auth?response_type=code&client_id=demo-app&redirect_uri=http%3A%2F%2Flocalhost%3A9100%2Fcallback&state=any-value-for-now

You end up at an error page, because nothing is listening at http://localhost:9100/callback. That is fine, and it is the point: look at your address bar. The code is right there, which is what passing through the browser means. Copy what comes after code=, which is the last thing in the address.

3. Trade the code for tokens

Put the code in place of PASTE_THE_CODE_HERE and run this in another terminal. A code works once, and lasts 5 minutes on this server, where a default one gives it one. So if this says invalid_grant, open the address from step 2 again for a new one. It will not ask for the password this time, because your browser still has its session.

curl -i -X POST 'http://localhost:18080/realms/demo/protocol/openid-connect/token' \
  -u 'demo-app:throwaway-client-secret' \
  --data-urlencode 'grant_type=authorization_code' \
  --data-urlencode 'code=PASTE_THE_CODE_HERE' \
  --data-urlencode 'redirect_uri=http://localhost:9100/callback'

The answer has your access token. It has the same parts as the recorded one on the diagram, with your own values.

When you are done

This stops the server and removes everything it knew, from any terminal. Docker keeps the image until you remove it, and your browser keeps the address with the code in its history, by then worth nothing. You can delete the folder.

docker rm --force authlines-demo

A scheduled job runs these commands against this version of the server, on Linux, for every combination of the settings above, so if they stop working, it fails. The advice for Windows is not part of that.

For example: SSO, refresh token, or the error on your screen.
